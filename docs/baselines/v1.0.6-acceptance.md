# LocalSpace v1.0.6 基线验收协议

## 1. 目的

本文件冻结 LocalSpace v1.0.6 的自动化和真实 ChatGPT/MCP 验收场景。后续版本必须复用这些场景进行前后比较；可以增加新场景，但不得删除失败或表现不佳的基线场景来改善表面结果。

本文件记录的是基线证据和待验收项，不代表计划中的后续能力已经受支持。

## 3. 自动化场景

### A01 — Runtime tool surfaces

- 启动 `minimal`、`full`、`codex`、`hybrid` 四种模式；
- 分别请求真实 MCP `tools/list`；
- 验证 Widgets `off` 的精确工具集合；
- 验证 Widgets `changes` 只增加 `show_changes`；
- 验证 Widgets `full` 不改变工具集合。

执行入口：

```text
npx tsx src/mcp-server-restart.test.ts
```

当前结果：通过。

### A02 — Stateless request concurrency

- 同时发送 8 个 `tools/list` 请求；
- 所有请求返回 HTTP 200 和非空工具集合；
- 不依赖 MCP Session ID。

当前结果：通过。

### A03 — Long process continuity

- `exec_command` 以 `yieldTimeMs: 0` 启动子进程；
- 返回 Process Session ID；
- 后续 `write_stdin` 能轮询到正常退出和完整关键输出。

当前结果：通过。

### A04 — Two independent processes

- 启动两个独立子进程；
- 两个 Session ID 不相同；
- 并发轮询两个 Session；
- 两个进程均以 Exit Code 0 完成。

当前结果：通过；这只证明独立进程生命周期可并存，不证明任意命令的文件系统副作用互不冲突。

### A05 — Loopback client benchmark

运行：

```text
npm run benchmark:mcp -- --output docs/baselines/v1.0.6-loopback-benchmark.json
```

该脚本创建临时 Git 仓库和临时 OAuth 状态，在本机启动 stateless hybrid MCP 服务并记录客户端观察到的 Loopback 往返时间。

基准包括：

- initialize；
- 连续 5 次 `tools/list`；
- 8 个并发 `tools/list`；
- `open_workspace`；
- `workspace_info`；
- `read`；
- `grep`；
- `project_map`；
- 两个独立 `exec_command` 及并发轮询。

该基准包含 HTTP、OAuth 验证、stateless MCP Server 创建、工具执行和 JSON 返回；不包含 ChatGPT 模型推理、公网 Tunnel 和浏览器 UI 时间。

## 4. 真实 ChatGPT 场景

### C01 — New conversation connection

步骤：

1. 新建 ChatGPT 对话；
2. 调用 `open_workspace`；
3. 调用 `workspace_info`、`read` 和一个搜索工具；
4. 确认 Workspace ID 可在后续请求复用。

v1.0.6 当前证据：通过。本路线规划对话已实际完成这些调用。

### C02 — Existing conversation after LocalSpace restart

步骤：

1. 在已有 ChatGPT 对话中打开 Workspace；
2. 重启 LocalSpace 服务；
3. 不刷新页面、不重新连接 App；
4. 继续使用原 Workspace ID 调用只读工具和多请求进程工具。

v1.0.6 当前证据：此前真实 ChatGPT 验收通过，仓库配置文档已记录 stateless 模式下该边界。后续版本必须重新执行，不得只依赖历史记录。

### C03 — Tool Search selectivity

步骤：

1. 在主机侧搜索 `open_workspace`；
2. 记录返回工具数和无关匹配数；
3. 搜索 `read`、`git_status`、`exec_command`；
4. 记录模型是否选择了正确工具。

v1.0.6 当前证据：存在选择性问题。大量工具描述重复 `open_workspace` 前置说明，搜索该词时会返回许多无关工具。该结果属于 E1 的优化基线，不应标记为通过。

### C04 — Native parallel MCP calls

步骤：

1. 提供三个互不依赖的只读任务；
2. 观察 ChatGPT 是否在同一模型轮次并行发出多个 MCP 请求；
3. 记录服务日志中的请求开始时间和重叠区间；
4. 区分主机原生并行与 LocalSpace 组合工具内部并行。

v1.0.6 当前证据：未确认。当前已证明服务端可以并发处理请求，但不能据此声明 ChatGPT 网页版会主动并行调用 LocalSpace 工具。

### C05 — Aggregate changes

步骤：

1. 在一次任务中修改多个文件；
2. 最终只调用一次 `show_changes`；
3. 确认展示范围覆盖本轮全部修改；
4. 再次调用时确认不存在重复范围。

v1.0.6 当前证据：常规单调用流程已使用；同 Workspace 并发 `show_changes` 尚未受控，不属于当前 supported 边界。

## 5. 比较规则

后续版本比较必须记录：

- MCP 请求数；
- 模型交互轮次；
- 客户端观察总耗时；
- LocalSpace 工具执行耗时；
- 排队耗时；
- 输出字符数和截断；
- 成功、失败、blocked 和 cancelled；
- Tool Search 无关匹配；
- 是否发生原生并行；
- 是否存在状态损坏或结果基于旧 Workspace 修订。

Loopback 基准只用于同机、同类环境下的相对比较。不同机器、Node 版本或负载之间不得直接以绝对毫秒数判断回归。

## 6. 当前基线结论

- 常规单仓库编程闭环可用；
- stateless MCP 能并发处理独立请求；
- 多个独立进程可同时存在；
- 工具面已冻结；
- Tool Search 选择性仍需修复；
- ChatGPT 网页版原生并行行为尚未确认；
- 同 Workspace 写操作、Git 写操作和同 Session 轮询尚无明确并发锁语义。
